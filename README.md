# RelGraph Studio · 关系叙事工作室

**Video-first, data-driven visualization of complex relationships.** RelGraph Studio turns domain data and declarative shots into a shared Canvas film. Literary and molecular-biology source semantics remain separate, and **any other set of things and relations loads through the generic `relgraph.graph/1` format** — an edge list is enough.

## Graph anything

```json
{
  "format": "relgraph.graph/1",
  "edges": [
    { "source": "Coffee", "target": "Caffeine", "kind": "contains" },
    { "source": "Caffeine", "target": "Adenosine receptor", "kind": "blocks" }
  ]
}
```

Save that as a `.json` file and drop it on the workspace, or run `npm run relgraph -- render it.json --out it.mp4`. Ids may be names in any script; undeclared endpoints become nodes. What the file does not say is derived: a layout chosen from the structure, hue, shape and dash rhythm per kind, size from weight or degree, a legend, and a storyboard that walks through the graph. Add `nodes`, `groups`, `kinds`, `weight`, `summary`, `visibleFrom` or your own `presentation` when you want control. The third built-in example, **线上书店**, is such a file with no coordinates and no shots. See [generic graphs, derived encoding and layouts](docs/GENERIC-GRAPH.md) for the format reference, the encoding rules, the ten layout strategies (`auto`, `force`, `layered`, `flow`, `tree`, `mindmap`, `timeline`, `radial`, `circle`, `grid`) and before/after frames.

**Flowcharts, mind maps, trees and timelines are the same graphs with conventions.** Add `"diagram": "tree" | "mindmap" | "flowchart" | "timeline"` and the document is laid out, routed and labelled the way its kind is read, and its film is derived to match: a tree or mind map unfolds one level per shot, a flowchart is walked step by step, and a timeline (nodes with `start` / `end`) travels along its axis. Four more example buttons show them: **进化树**, **朝代更替**, **读书会** and **订单流程**. See [diagram kinds](docs/GENERIC-GRAPH.md#diagram-kinds).

## Run the director workspace

Use Node.js 20.19+ on the 20.x line, 22.13+ on the 22.x line, or 24+. Install the pinned development dependencies and start the local Vite server:

```bash
npm ci
npm run dev
```

Open **http://127.0.0.1:5173/demo/** in a desktop browser. The workspace loads the provisional literary example at startup; switch to the canonical EGFR–MAPK biology example or the generic bookshop example, or select / drag-and-drop a local JSON file. The file is read locally in the browser. Vite compiles the TypeScript modules, so the integrated workspace cannot be served directly by `python -m http.server` or opened using `file://`. To serve a production build locally, run `npm run build` followed by `npm run preview` and open the `/demo/` URL printed by Vite. The older [standalone prototype](demo/standalone.html) remains directly openable as a historical demo; it is not the integrated player.

**Interface languages:** The integrated Director Studio supports **中文 / English** via the **界面语言 / Interface language** selector in the top bar. The choice is stored in browser storage (default: Chinese), and switching does not reload source data, stop playback, discard edits, or change exported graph content. The editor localizes workspace controls, hints, and diagnostics but never auto-translates authored graph labels, scene narration, or video frames. The historical standalone prototype remains Chinese-only. The workspace makes no network requests other than to its local server and does not require accounts or databases.

- The workspace and the rendered film share a light (paper) or dark theme. It follows the operating system until you pick one with the theme button; the choice is remembered in this browser. `renderAt` draws with the current theme, and `createCanvasRenderer(..., {theme: 'light' | 'dark'})` takes it as an explicit input, so a frame stays deterministic per theme.
- Play, pause, restart, drag the frame timeline, or select a shot. Space toggles playback outside focused controls; left/right arrows seek by one second.
- Both source formats use the same validation → domain adapter → `VisualGraph` → display-list composition → Canvas pipeline as the headless exporter (see below). Errors and warnings appear separately with a field path, object ID when available, explanation and repair advice.
- The time in the player is **video time**; `chapterAt` / `domainAt` is **domain time**. `presentation` compiles to pure keyframe tracks after spoiler projection: domain-time advances fade/scale new nodes in 0.6 seconds and draw new edges along their exact curved paths in 0.8 seconds; a backwards domain step removes them instantly. Shot title and narration fade in and out over 0.3 seconds, except that the last shot's caption stays until the final frame; a node's detail card appears with its label, halfway through the node's reveal; camera and highlight interpolation retain their former values. If any objects have visibility intervals, the first shot must specify a domain time. Future graph objects and references are filtered before rendering. If a shot explicitly refers to an invisible object, its title and narration are withheld as well. Non-active shot titles are withheld because scene order can move backward in domain time.
- Author-provided free text is not automatically fact-checked or semantically censored: write titles, narration, biography summaries and relationship labels for the intended point in the story. Untimed source data cannot provide reliable chapter-level spoiler protection. The provisional Honglou example intentionally has no invented chapter timestamps.
- Node positions provided in JSON are preserved. A document with no positions at all is arranged from its structure by the `auto` layout; otherwise missing positions use a deterministic static fallback that never moves authored nodes. No physics runs during playback. Overlapping authored positions and very dense graphs can still need manual editing.

### Local verification

```bash
npm test
npm run typecheck
npm run check:types
npm run lint
npm run format:check
npm run build:packages
npm run build
npm run check:browser
npm run check:export
```

The Vitest suite covers adapters, source diagnostics, spoiler projections, reaction roles, camera interpolation, timeline compilation, reveal boundaries, accurate partial Bézier paths, static layouts, deterministic display lists (including spoiler-filtered accessible text and exact 720p → 1080p scaling), domain style sheets, the Canvas backend's translation and workspace behavior. It also separately builds and packs the packages, installs the tarballs in an isolated consumer and checks their runtime and TypeScript interfaces against both examples. The workspace, core and renderer are checked with strict TypeScript, ESLint and Prettier. Workspace tests use a simulated DOM, so `npm run check:browser` additionally builds the studio, serves it with `vite preview` and drives it in headless Chromium through the pinned Playwright dev dependency. It covers both examples, file selection, malformed and schema-invalid files, drag-and-drop, playback, seeking, keyboard shortcuts, theme switching and persistence, deterministic `renderAt` frames, console errors and non-local requests. If Playwright has no browser installed yet, run `npx playwright install chromium` once. The check also saves mid-shot frames of both examples in both themes to `output/browser-check/`. Before a rendering change, run `npm run check:browser -- --update-reference` to save them as a local baseline in `output/browser-reference/`; later runs on the same machine fail when more than 0.5% of a frame's pixels differ. The baseline is not committed because pixels depend on the browser version and fonts; with a different Chromium version or platform the comparison is reported but not enforced. Use `--no-build` to reuse an existing `dist/`. Changing fonts or rasterization intentionally changes these frames, so re-save the baseline afterwards.

`npm run check:export` (FFmpeg and ffprobe required; not part of `npm test`, which stays fast) builds the packages and checks the headless export. It compares 236 key frames (each shot's middle; from the second shot, the mid-reveal frame 0.3 s in and the mid-transition frame; and the last frame, for five examples in both film themes at 1080p) with the SHA-256 hashes in `examples/golden-frames.json`. They are enforced only when skia-canvas and the vendored fonts match the recorded versions; otherwise differences are reported without failing, like the browser baseline. It then exports those five examples as MP4 with `relgraph render` and verifies with ffprobe the codec, `yuv420p`, 1920 × 1080, 24 fps, BT.709 tags, a decoded frame count equal to `frameCount(graph, fps)` and the matching duration. It decodes a mid-transition frame from each video and compares it with the PNG that `relgraph render --frames` writes for the same index: the PNG must equal the in-process render exactly, and the decoded frame must match it (at least 35 dB PSNR) better than its neighbours. It muxes test tones (made by FFmpeg at check time) shorter and longer than two of the films with `--audio`, also for a frame range, and requires the decoded video frames to equal the silent MP4's by framemd5, a length warning, and an AAC track as long as the video; and it requires `relgraph events` and `relgraph render --events` with `--jobs 1` and `--jobs 3` to write byte-identical event files. Finally it reports, for information, how far the browser preview and the headless export differ at 720p. Outputs go to `output/export-check/`. Run `npm run check:export -- --update` to rewrite the golden hashes after an intended rendering change, and use `--no-build` or `--no-browser` to skip steps. `npm test` also checks all 236 committed golden frames across the five examples and both themes when the Skia version and fonts match; MP4 encoding remains in `check:export`. To regenerate the font subsets, see [packages/render/fonts/README.md](packages/render/fonts/README.md).

The literary validator reads the JSON Schema directly and derives the checked document type from it; the biological adapter checks the values it consumes before narrowing imported data. After editing the literary schema, run `npm run generate:types` and commit the regenerated types. `npm run check:types` detects a stale generated file.

The source is organized into the npm workspaces `@relgraph/core` (model, schema, validation, domain adapters, projections, layout, timeline compilation and director state), `@relgraph/render` (frame specs, display-list composition, video themes, renderer captions, vendored fonts, the Canvas 2D backend and, in the Node-only `@relgraph/render/skia` entry, the skia-canvas backend) and `@relgraph/cli` (the `relgraph` command), plus `apps/studio` (workspace behavior). `demo/index.html` remains the integrated entry point. The studio's Vite and TypeScript configuration resolves these package names to workspace sources, so `npm run dev` and `npm run build` do not require prebuilt packages. Installed consumers use the packages' explicit ESM and type exports instead.

Use `npm run build:packages` to build core, render and the CLI in that order, emitting JavaScript and declarations to each package's `dist/`. The individual commands are `npm run build --workspace=@relgraph/core`, `--workspace=@relgraph/render` and `--workspace=@relgraph/cli`; each requires current builds of the packages before it. skia-canvas is an optional peer dependency of render (only `@relgraph/render/skia` needs it) and a dependency of the CLI. The packages are private and are not published. The schema at `packages/core/schema/relationship-graph.schema.json` is the single source used for both runtime validation and generated types; the core build emits a derived copy into its output, including in package tarballs.

The development-only `minimatch` override temporarily selects the patched 11.x release for a glob denial-of-service advisory. It crosses the lint tools' declared 10.x dependency range; keep the lint checks when updating dependencies and remove the override when those tools support a patched version themselves.

The browser workspace additionally exposes `window.renderAt(frame)` for a validated integer frame in the loaded film and `window.studioFrame()` for its current safe state. The studio canvas uses the `landscape-720p` frame spec (1280 × 720 at 24 FPS); `renderAt` pauses playback and redraws independently of prior frames. The workspace loads the vendored film fonts before its first frame. Pixel identity in the browser is expected within the same browser version and rasterizer; for video output use `relgraph render`, whose frames are reproducible for the same skia-canvas version and fonts.

## Customize the network

Use the right-side **画面与属性** panel for safe node/edge selection, sparse inherited styles and display-only copy. **Document-wide actions are in one toolbar above the film preview**: Undo/Redo, **保存完整项目** (download `.studio.json` including styles, copy and coordinates), and **仅导出坐标 JSON** (source document coordinates only, **not** a full-project save). The toolbar shows unsaved status and download/validation feedback. Plain source files remain compatible; Studio projects also render through the CLI. See [configuration and reproduction](docs/NETWORK-AUTHORING.md).

For document history, use `Ctrl/⌘+Z` to undo and `Ctrl+Y` or `Ctrl/⌘+Shift+Z` to redo. `Ctrl/⌘+S` starts a guarded complete-project download; confirm that the browser retained the file. **Native undo/redo in text, number and selection inputs remains untouched.** Pending invalid or unsubmitted editor drafts block the full save, and holding a save shortcut does not trigger repeated downloads. The browser retains the existing source-switch and page-exit warnings.

Advanced appearance fields display the core's allowed numeric range and an inline accessible error before invalid values enter history. Six-digit hex color fields pair text entry with a native swatch/picker; empty means inherit, and ↺ clears drafts without creating a no-op edit. Rejected numeric and color drafts remain available when changing the selected object or playing through frames.

At desktop and medium widths (841px and above), the data/inspector sidebar scrolls independently of the video preview, so changing properties no longer requires scrolling away from the canvas. The current selection is outlined on a separate, pointer-inert SVG layer over the preview. Object scope highlights one node/edge; category and global scopes outline currently drawn members and report the count in the **current spoiler-safe projection**. A projected object that has not yet appeared in the drawn frame is counted but not outlined. Manual position editing highlights its selected node. The layer is **workspace-only**: it is not saved in the project and does not change the Canvas bitmap, `FrameSpec`, `DisplayList`, PNG or MP4 output. On narrower screens the inspector stacks below the preview.

Uploaded node images are supported through the node property panel: PNG/JPEG/WebP, shape clipping, cover/contain, undo and self-contained project saving. See [limits, offline export and current main-branch delivery](docs/NODE-IMAGES.md).

The document toolbar shows **未保存修改** when the current document differs from the last imported or complete-project-exported state, including temporary layout previews and pending inspector edits. Switching examples, importing a file or dropping JSON asks for confirmation before discarding edits; cancelling leaves the current document and undo history untouched. Closing or reloading a dirty page uses the browser's native unsaved-changes warning where supported. **保存完整项目** begins a complete `.studio.json` download and establishes a new working savepoint; confirm that the browser actually saved the file. **仅导出坐标 JSON** saves only source coordinates and does not clear the unsaved-project indicator. This is not autosave and there is no server-side persistence.

## Prepare deterministic coordinates before filming

Use `relgraph layout` to fill **only missing** node coordinates. Existing authored coordinates are never moved, including reaction/process positions. Each new node goes beside the nodes it is related to: it starts at their barycentre, offset in the direction the engine the player would choose gives it, and moves to the nearest place that keeps clear of other nodes and relations; on a timeline that keeps time it stays at its years, in the free lane nearest its neighbours' lanes (ADR 004, D2b). The layout runs before playback; it adds no physics to the renderer or timeline. `relgraph check-layout` checks the result as drawn.

```bash
npm run build:packages
npm run relgraph -- layout story.json                    # preview, no write
npm run relgraph -- layout story.json --seed 42 --out arranged.json
npm run relgraph -- layout story.json --seed 42 --write # atomically replace source
npm run relgraph -- layout poets.json --chronology-tolerance 20 --out placed.json
```

`--chronology-tolerance N` is for drawings whose x means time without being a timeline that keeps time (the Tang poet networks): a new node whose time differs from a placed node's by at least `N` goes on the side of it that its time says, as `relgraph check-layout --chronology-tolerance N` checks. A node's time is the one `check-layout` uses. Existing coordinates still never move, so a node whose placed neighbours are already out of order is placed without the constraint. A document without any coordinates is arranged from its structure as usual; with the option, that drawing is written only if it is already in time order, and otherwise the command fails without writing.

The same document and seed produce the same coordinates regardless of JSON node ordering. Literature positions go to `characters[].position`; biology positions go to `entities[].position` and `processes[].position`. The CLI validates the serialized document before writing, refuses to overwrite an existing `--out` destination, and leaves the source untouched by default. The existing `layoutGraph` fallback still handles imported documents without saved coordinates in the player.

## Director workspace architecture

For ADR 003 step 5, position authoring is deliberately split across three boundaries:

- `layout-editor-model.ts`: **DOM-free** editing policy, visible-node eligibility, relative drag math, coordinate validation, changes/reset. Test the model directly without browser mocks.
- `position-tool.ts` and `@relgraph/render`: pure coordinate transforms and shared camera projection.
- `layout-editor-view.ts`: **DOM-only** rendering for the edit panel, node dropdown, status text and coordinate inputs.
- `studio.ts`: browser event adapters (pointer capture, form input reading, redraw, file download), delegating to model + view. No duplicate drag or visibility math.

The pure `studio-mode-model.ts` decides whether playback, position editing or a temporary layout preview must exit when the user navigates, changes themes, plays or applies a layout. `studio.ts` executes those transitions in one place while retaining the existing authoritative playback clock, preview snapshot, pointer transaction and request serial. Preview cancellation restores coordinates; applying preview commits them through project history. Changing themes does not stop ongoing playback, and switching modes cancels an unfinished drag rather than committing stale pointer-up data.

The shared `tests/helpers/studio-harness.mjs` covers cross-component DOM integration; older standalone workspace DOM stubs have been migrated to it. Render/video golden tests exercise the composition layer separately. Playback policy lives in `playback-model.ts`; playback, shot, diagnostic and transcript DOM updates have focused view adapters. The transcript consumes only `DisplayList.a11y`, with pure semantic snapshots in `transcript-model.ts`. `studio.ts` retains scheduling, event routing and request-serial guards. See the [B1.5 final acceptance report](docs/B1.5-FINAL-ACCEPTANCE.md) for verification and the B2 merge gate.

## Tweak positions in the director workspace

The **调整节点位置** button pauses playback and locks the current shot camera. Drag visible nodes to refine coordinates; hidden nodes cannot be selected. Keyboard-only users can choose a currently visible node in **当前可见节点**, type numeric **X 坐标** / **Y 坐标**, then activate **应用坐标**. The selector does not reveal future or hidden nodes. Press **Esc** to leave edit mode. Seeking or changing themes also returns to normal camera behavior. **重置调整** restores the original layout. Edits live only in the current browser session until **保存完整项目** downloads a full `.studio.json` or **仅导出坐标 JSON** downloads a new source file containing the edited coordinates. The latter does not persist style or display-copy edits. The exported source contains every resolved position (including fallback coordinates for previously missing nodes) and is validated by the same source validator used for imports. Import the exported file or render it with the CLI to reuse the edited positions. Exiting edit mode, switching themes, and ordinary playback do not persist anything.

## Export a film without a browser

Combine native Studio rendering with external illustrations, music and editing using the [collaborative video workflow and runnable portrait example](docs/VIDEO-WORKFLOW.md).

The `relgraph` command line (`packages/cli`) renders a document with the same composition code as the workspace, drawn by [skia-canvas](https://skia-canvas.org) instead of a browser canvas, and encodes the frames with FFmpeg.

Requirements:

- The Node.js versions above. `npm ci` installs skia-canvas 4.0.0, whose prebuilt native module comes from an npm package for your platform (macOS, Linux glibc/musl or Windows, x64 or arm64); nothing is downloaded from GitHub and no compiler is needed.
- For MP4 output, [FFmpeg](https://ffmpeg.org/download.html) with the libx264 encoder, on `PATH` or passed with `--ffmpeg <path>` (macOS: `brew install ffmpeg`; Debian/Ubuntu: `sudo apt install ffmpeg`; Windows: `winget install Gyan.FFmpeg`). PNG frame sequences need no FFmpeg. Without a usable FFmpeg, `relgraph render --out` stops before rendering and says how to install one.

```bash
npm ci
npm run build:packages
npm run relgraph -- validate examples/honglou-provisional.relgraph.json
npm run relgraph -- render examples/honglou-provisional.relgraph.json --out output/honglou.mp4
npm run relgraph -- render examples/biology-egfr-mapk.json --frames output/bio/%05d.png --theme dark --from 96 --to 120
npm run relgraph -- events examples/biology-egfr-mapk.json --out output/bio.events.json
npm run relgraph -- render examples/biology-egfr-mapk.json --out output/bio.mp4 --audio music.wav --events output/bio.events.json
```

`npm run relgraph -- …` runs `packages/cli/dist/bin.js`; after `npm run build:packages`, a later `npm install` also links `npx relgraph`. Installed from its package, the binary is called `relgraph`.

- `relgraph validate <file> [--json]` prints the same errors and warnings as the workspace (code and record ID, JSON path, explanation, `建议：` fix) and exits with status 1 when there are errors. Among the warnings, `CAPTION_READING_SPEED` names each authored shot whose title and narration take longer to read (9 CJK characters, or 17 other letters and digits, per second) than the caption is fully shown, with the shortest `durationSec` that would do; derived storyboards are not checked, and durations stay as written.
- `relgraph render <file> --out film.mp4 | --frames out/%05d.png` renders every frame (or `--from N --to M`, inclusive, counted from 0) in parallel worker threads (`--jobs N`, default up to 8). The frame count is `frameCount(graph, fps)`. Options: `--frame-spec landscape-1080p` (default; `landscape-720p` matches the workspace preview's landscape size; `portrait-1080x1920`, `portrait-1080x1440` (3:4) and `square-1080` have their own safe areas, legend strip, evidence-card place and four narration lines, see [ADR 004](docs/ADR-004-evidence-claims-and-output-formats.md) D7; the workspace's **画面规格 / Frame** menu previews the same specs; a Studio project's `config.view.timeAxis: "vertical"`, set from the workspace's **时间轴 / Time axis** menu, draws time from top to bottom as a render-time transpose of the stored coordinates, never inferred from the spec and with no CLI switch, and `render` warns when a portrait spec draws a horizontal time axis, ADR 004 D7 step 2), `--theme light` (default) or `dark`, chosen independently of the workspace theme, and `--locale zh-CN` (default) or `en` for renderer captions. A project's `config.view.mode: "list"`, set from the workspace's **画面形式 / View** menu, shows the same film as a time-ordered list of rows (time, name, summary and relations written out) instead of a network drawing; see [list form](docs/NETWORK-AUTHORING.md).
- After rendering, `relgraph render` lists per shot the labels that its settled frames (after the camera transition and the reveals at the shot's start) could not place, because every place would leave the stage or cover other text. `--fail-on-omitted-labels` makes that an error after the output is written. `relgraph check-labels <file> [--frame-spec …] [--locale …] [--json]` reports the same without rendering: it composes the first, middle and last settled frame of every shot and exits with status 1 when a label is left out. The studio names the labels the current frame leaves out under the preview. See [ADR 004](docs/ADR-004-evidence-claims-and-output-formats.md), D1.
- A shot can show an evidence card: the verbatim quotations and citations of one node or relation (`evidence` in `relgraph.graph/1`; see [evidence cards](docs/GENERIC-GRAPH.md#evidence-cards)). Card text is never cut, and the card waits for the camera so it never covers its subject: `relgraph render` refuses a film whose card does not fit or would never be shown, before writing anything, and `check-labels` reports it (ADR 004, D4).
- `relgraph check-layout <file> [--frame-spec …] [--locale …] [--clearance px] [--crowding px] [--chronology-tolerance N] [--json]` checks, in the same settled frames, relations drawn within `--clearance` (720p pixels, default 4) of a node they do not join or across it, and glyphs within `--crowding` (default 2) of each other; bars on a time axis may abut but not overlap. Gaps are measured between what is painted: each glyph's drawn outline and border, and each relation's whole drawn path, bow included, with its stroke width, so this also finds what a straight-line check of the coordinates misses. With `--chronology-tolerance N` it also checks the stored layout: of two nodes whose times (the mean `visibleFrom` of their timed relations, else their own) differ by at least N, the earlier must be drawn further left (further up in a project drawing time vertically, whose frames are checked as drawn). It exits with status 1 when it finds anything.
- `relgraph events <file> [--frame-spec …] [--out events.json]` writes the film's events without rendering it (to standard output without `--out`); `relgraph render … --events events.json` writes the same file once the output is complete. The format is `relgraph.events/1`: `fps`, `frameCount`, `durationSec`, a `nodes` table and `events` ordered by frame. Each event has `frame` (the first frame that shows it, counted from 0), `sec` (its instant on the timeline), `shot` (index from 0), `type` and `id`. `shot` events give the shot's `frame`–`lastFrame` (inclusive) and `frames`, `settledFrame` (after the camera move and the reveals at its start, as `check-labels` uses; null if it never settles), the highlighted `nodeIds`, `edgeIds` and `groupId`, `domainAt` and `revealStep`; `caption` events the title and narration with their fades; `domain-time` events the new `value` and the `previous` one; `evidence` events the shot's evidence card, on the frame it begins to fade in: `object`, `target` and the shown `items` (indices into the object's evidence); `reveal` events `object` (`node` or `edge`), `kind`, `group` (for a relation, the group both ends share, else null), `effect` (`fade`, `draw`, or `none` for what the first shot shows outright) and its `durationSec`, a relation's `source` and `target`, and `outFrame` when going back in domain time withdraws the object again (on a frame: a step back shorter than a frame is not an exit). The `nodes` table lists every node a frame shows, with its id, drawn label, kind, group and world coordinates (`x`, `y`, as laid out for the film), so music can follow the picture without reading the graph. Events come from the compiled timeline after spoiler projection, so nothing is named before the film shows it; frames are those the renderer assigns (a reveal's `frame` is the first frame of its fade or draw-on; the frame before does not show the object), and a shot shorter than one frame, which no frame shows, has no events at all (a gap in the `shot` indices). Ids are the source document's own. Only the frame spec's rate affects the file, and the same document always gives the same bytes, at any `--jobs`. Neither command writes an output over the document, the `--audio` file or another output (symlinks and hard links included, and every frame file of `--frames`); it refuses before writing anything. Paths that do not exist yet and differ only in case or Unicode normalization (`Film.mp4`, `film.mp4`) count as one file, as they are on Windows and default macOS.
- `relgraph render … --out film.mp4 --audio track.wav` muxes an existing sound file (anything FFmpeg reads) into the MP4 as AAC (192 kb/s). The video is encoded as without sound and its stream copied, so the decoded frames are identical (checked by framemd5 in `check:export`). The video's length wins: a longer sound is cut, a shorter one ends in silence, and a difference of more than one frame is a warning; the length is where the first audio stream ends, not the file's (a video file's picture may outlast its sound). With `--from N`, the sound starts at frame N's time. Relgraph Studio composes no sound itself; see [ADR 004](docs/ADR-004-evidence-claims-and-output-formats.md), D3.
- MP4 output is H.264 (libx264, CRF 16), `yuv420p`, converted from sRGB with the BT.709 matrix and tagged BT.709 limited range, at exactly the frame spec's rate (24 fps), with one video frame per rendered frame. `--frames` writes lossless RGBA PNGs named after the absolute frame index, using `%d` or `%0Nd` like FFmpeg.

Every frame is a pure function of the document, layout, frame index and options, so any single frame can be re-rendered on its own (`--from N --to N`) and is pixel-identical to the same frame in a full export. Text uses the vendored [Noto Sans / Serif / Sans Mono CJK SC subsets](packages/render/fonts/README.md) (SIL OFL 1.1), which both the workspace and the exporter register under the names that lead `FONT_STACKS`. They cover the examples and bundled datasets, the renderer copy, all 6,763 GB 2312 hanzi (levels 1 and 2), Latin and common punctuation (7,818 characters in every face, listed in `packages/render/fonts/coverage.txt`). `relgraph render` warns when a document uses characters outside the subset, because those fall back to system fonts. Pixels are meant to be reproducible across machines with the same skia-canvas version and fonts: rendering uses skia-canvas's CPU rasterizer, never the GPU, and the registered fonts take precedence over installed fonts of the same name. The committed [golden frames](examples/golden-frames.json) record both versions and the platform they were made on (so far linux-x64); `npm run check:export` on another platform shows whether its hashes agree. Programmatic use: `createHeadlessRenderer` from `@relgraph/render/skia` and `renderFilm` from `@relgraph/cli`.

## Source data and scope

- [Source-verified Honglou opening subset](datasets/honglou-chengjia-opening/graph.relgraph.json): 6 people and 9 relations from the 1791 Chengjia edition, chapters 2–3; 8 direct textual confirmations and 1 explicitly labelled kinship inference. The [verification report](datasets/honglou-chengjia-opening/VERIFICATION.md) maps every fact to short evidence, pinned source revisions and scan pages; the [B2-2 handoff](datasets/honglou-chengjia-opening/B2-2-HANDOFF.md) proposes a 75-second film. The file's three-second presentation is a data-validation scaffold, not the formal film. Import it as local JSON; the built-in examples remain unchanged. `npm run check:honglou-sources` optionally rechecks the public sources with `curl`, outside the local-first studio and ordinary offline test suite.
- [Riemann Hypothesis timeline film](datasets/riemann-hypothesis/README.md): 66 people, results and events from Euler's product (1737) to the November 2026 Lean proof, as a vertical-time-axis Studio project with 17 shots and a list-form project; both 3 min 53 s portrait films are rendered entirely by `relgraph render` (the videos are not committed; the dataset README gives the commands). Recent claims are limited to what primary sources state (arXiv:2609.02882 and the Lean FRO / Mathlib Initiative statement of 2026-11-21); older citations are compiled from the standard literature, not checked against scans.
- [Literary draft and example](examples/honglou-provisional.relgraph.json): 17 characters, 17 relations and five shots. **This is provisional, not source-verified literary scholarship.** See the [JSON Schema](packages/core/schema/relationship-graph.schema.json) and [TypeScript types](packages/core/types/relationship-graph.ts).
- [Canonical EGFR–MAPK biology example](examples/biology-egfr-mapk.json): a simplified, provenance-linked teaching network covering receptor activation, RAS switching, the RAF–MEK–ERK cascade, nuclear response and negative feedback. It is **not** a quantitative or species-complete model; `relgraph.bio/0.1-draft` is not PSI-MI, SBGN, SBML or BioPAX.
- [Generic example](examples/bookshop-systems-synthetic.graph.json): a fictional online bookshop's systems as `relgraph.graph/1` — 15 nodes of four kinds in four groups, 20 weighted relations of three kinds including a self-relation, and nothing else. **It describes no real system.** The [generic adapter](packages/core/src/domains/generic.ts), [layout engines](packages/core/src/director/layout-engines.ts) and `styleForGraph` in [style.ts](packages/core/src/style.ts) do the rest.
- Diagram examples, all `relgraph.graph/1`: a [vertebrate tree](examples/vertebrates-tree-provisional.graph.json) of 22 clades and [Chinese dynasties on a timeline](examples/dynasties-timeline-provisional.graph.json) with 18 spans — **both simplified to textbook level and not checked against sources item by item** — plus a [reading-club mind map](examples/reading-club-mindmap-synthetic.graph.json) and an [order flowchart](examples/order-flowchart-synthetic.graph.json), both fictional.
- [Neutral graph contract](packages/core/src/graph/core.ts), [literature adapter](packages/core/src/domains/literature.ts), [biology adapter](packages/core/src/domains/biology.ts), [director state](packages/core/src/director/state.ts), [domain style sheets](packages/core/src/style.ts), [frame specs](packages/render/src/frame-spec.ts), [display-list composition](packages/render/src/compose.ts), the [Canvas backend](packages/render/src/backends/canvas2d.ts), the [skia-canvas backend](packages/render/src/backends/skia.ts) and the [CLI](packages/cli/src/index.ts) are reusable modules. `createCanvasRenderer(canvas, graph, layout, {frameSpec, theme, locale, style})` draws frames and `displayListAt(frame)` returns a frame's display list without drawing it. `renderFrameWithList(frame)` returns the exact drawn frame state and its `a11y`-bearing display list for the studio transcript; `compileTimeline(graph, fps)` is exported from core and does not mutate source data.

ADR 003 step 4 was accepted after measuring its pixels against `main`: all 16 browser mid-shot frames and 28 of the 32 previous golden frames are byte-identical, and the 4 that changed are the biology frames where new edges are still being drawn (111 and 231, both themes). 12 mid-reveal golden frames were added.
